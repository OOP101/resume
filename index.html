直播带货 AI 话术助手 独立开发（课程实践项目） 2026/08 – 2026/09
项目背景

直播带货场景下弹幕信息量大、节奏快，主播需同时兼顾商品讲解、互动与促销引导，难以实时捕捉购买意向、价格疑虑、竞品对比等关键信号。本系统以 LangGraph 状态机编排多步 Agent 工作流，将弹幕经意图识别后按类型路由至 RAG 检索，结合商品知识与历史话术生成可直接口播的推荐话术与执行策略，并通过 WebSocket 实时推送至前端。

技术架构

Python + FastAPI + LangGraph StateGraph + LangChain + RAG（ChromaDB 向量检索 + doc_type 过滤）+ SQLAlchemy 异步 / SQLite + WebSocket + Vue3 + TypeScript + Pinia + Element Plus + ECharts

主要职责
  • 设计并实现 LangGraph StateGraph 六节点工作流（预处理 → 意图识别 → RAG 检索 → 话术生成 → 策略推荐 → 结果整合），以 TypedDict 定义跨节点共享状态，统一承载意图、情感、检索来源、话术与策略字段。
  • 构建弹幕意图识别链路：以结构化输出约束 LLM 返回意图类型、置信度、情感倾向与关键词，覆盖购买意向、产品疑问、价格疑虑、负面情绪、互动闲聊等 6 类意图。
  • 搭建 ChromaDB 向量检索链路：商品知识与话术模板两类文档经 embedding 入库，元数据标记 doc_type 以支持过滤检索，采用余弦相似度、top_k=5。
  • 实现按意图路由的检索策略并设计兜底：产品疑问类走商品知识库、购买意向与价格疑虑类走话术库，命中不足时回落全库检索，避免答非所问。
  • 基于 FastAPI 提供 HTTP + WebSocket 双通道：弹幕经 WS 端点接入后触发 Agent 处理，连接管理器统一广播分析结果，支持前端多端订阅。
  • 设计话术生成与策略模板：Prompt 约束口语化表达与 50~150 字长度、返回 script/strategy/urgency 结构化结果；5 类意图分别映射优先级与执行动作（购买意向→立即引导下单，负面情绪→安抚与补偿方案）。
  • 建模 SQLite 数据层：商品、弹幕记录、话术库、分析结果、直播会话、知识库文档 6 张表，使用 SQLAlchemy 异步会话持久化弹幕与分析结果。
  • 前端基于 Vue3 + TypeScript 实现：Pinia 状态管理、WebSocket 客户端接入、ECharts 呈现弹幕趋势与意图分布。
项目难点 · 解法 · 结果
  • 难点：大模型输出 JSON 不稳定，单节点失败会打断整条链路——LLM 返回直接解析，格式漂移即抛异常。解法：提取首个 { 至末个 } 的容错解析，失败回退纯文本话术，每个节点配独立异常兜底与默认值。结果：任一节点异常均不中断整条工作流，仍向下游返回可用结果并记录错误。
  • 难点：意图类型与检索范围错配，话术答非所问——初版全库检索，价格类弹幕常命中产品参数文档，生成话术像念产品手册。解法：按意图做 doc_type 过滤路由（产品疑问 → product、购买/价格 → script），命中不足 2 条时回落全库检索。结果：不同类型弹幕各取所需知识，话术与场景匹配度明显提升。
  • 难点：直播实时性要求与多节点串行链路的矛盾——单条弹幕需串行经过 6 个节点（含 2 次 LLM 调用），链路长、延迟叠加。解法：批处理参数控制节奏（BATCH_SIZE=10、ANALYSIS_INTERVAL=5）、WebSocket 单次广播替代逐端请求、低置信度（<0.6）弹幕降优先级避免无效生成。结果：端到端延迟控制在秒级（设计目标 < 2s）。
企业智能知识中枢（RAG 底座） RAG 应用开发工程师 2026/05 – 2026/09（至今）
项目介绍

企业内部 SOP、技术文档、规章制度往往散落在共享盘、群文件与个人电脑中，新人上手只能依赖老员工口头带教，同一问题反复问、答案还不一致；而通用大模型直接提问容易出现幻觉、答不出处，制度类内容一旦答错就是合规风险。本项目将分散的企业知识统一归集为可自然语言检索的问答服务，构建「文档解析入库 → 混合检索召回 → 融合精排 → 大模型生成带来源答案」的完整链路，员工提问即可拿到引用原文的标准答案，支持多轮追问与跨文档检索；同时提供文档上传与知识库管理后台、按知识库隔离的权限控制，是面向企业内部的知识问答基础设施，可直接复用到客服知识库、研发文档问答等场景。

技术架构

Python + LangChain + LangGraph + FastAPI + ChromaDB + LLMManager 多模型兼容层 + jieba 分词 + BM25 稀疏检索 + RRF 融合 + PyMuPDF/python-docx 自研解析器 + 中文标点感知文本分割 + SSE 流式输出 + Docker Compose

主要职责
  • 自研多格式文档解析器，支持 PDF、Word、Markdown 等格式自动加载与中文标点感知智能切片，经向量化后高效入库；基于 doc_id 实现文档定向重建与分片级增量更新（chunk_hash 指纹复用未变分片），新 SOP 上传后分钟级生效，避免全库重灌。
  • 自研 HybridRetriever 混合检索器，协同调度 Chroma 向量召回与 BM25 稀疏召回，经 RRF 融合排序后接入可插拔精排器二次重排，精准解决专业术语场景下纯语义检索命中不稳的难题。
  • 基于自研会话记忆组件按 session_id 分桶保存最近 N 轮对话历史，检索时拼接上下文交由 LLM 生成答案，有效支持指代消解与多轮追问；按轮数动态裁剪上下文窗口，抑制长会话下的记忆膨胀。
  • 封装 LLMManager 多服务商注册表（DeepSeek/Qwen/OpenAI/Moonshot），运行时切换模型业务代码零改动，配置持久化重启自动恢复。
  • 搭建 FastAPI 服务层，封装知识问答、文档上传、知识库管理等 RESTful 接口，对话接口 SSE 流式输出前端逐字渲染；按 kb_id 实现多知识库隔离与权限控制。
  • 基于 LangGraph 构建 StateGraph 有状态工作流：classify（规则+LLM 意图分类）→ route（条件路由）→ knowledge/action/list 节点 → memory_writer → END，注册知识库查询 / 流程发起 / 流程列举三类工具，实现"查完即办"闭环。
项目难点
  • SOP/制度类文档专业术语、缩写密集，纯语义检索命中不稳：Dense+BM25 双路召回经 RRF 融合（K=60），再接可插拔 Reranker 三档（本地规则/Qwen 在线/BGE 本地），失败自动回退本地规则。
  • SOP/制度高频更新，检索索引全量重建成本高：按分片内容指纹（chunk_hash）做增量，同一文档只增删变更分片、复用未变分片，改版 SOP 分钟级生效。
  • 长会话记忆膨胀与 Token 成本失控：按 session_id 分桶保存最近 N 轮 + 按轮数裁剪窗口，超 Token 预算自动触发上下文压缩；无 API Key 时自动切换 DemoLLM 与规则引擎兜底，全链路离线可验证。

Python + FastAPI（三服务微服务架构）+ LangGraph StateGraph + React 19 + APScheduler 定时轮询 + 可插拔 Embedding 三后端 + SSE 流式输出 + Prometheus 指标 + 结构化 JSON 日志与链路追踪

主要职责

  • 完善安全与数据治理：收窄鉴权后门（dev 万能 key 仅开发环境生效）、补齐行程属主校验防越权访问（IDOR）、修复相对数据路径按服务工作目录解析导致的数据孤岛问题并完成存量数据迁移合并。
  • 推进工程化建设：将 1200 行单体路由文件按领域拆分为 7 个 APIRouter 模块，编写六项端到端自动化验证（生成 / 越权 / 阻塞 / 并发 / 政策审批链路 / 流式）与幂等种子数据脚本，全链路接入 Prometheus 指标、结构化 JSON 日志与链路追踪。
项目难点
  • 大模型生成多日行程耗时长（数十秒），且早期 async 路由中同步调用 LLM 会阻塞整个事件循环，单请求即可卡死全部服务。通过流式协议改造（逐 token 透传 + 独立错误帧）与线程池化，实现问答首字 1.3 秒、行程生成全程可感知，服务在长耗时请求期间保持健康响应。
  • 多用户并发使用时存在一致性问题：全局生成器单例被并发请求互相覆盖模型配置、共享解析结果导致"串单"；JSON 文件存储并发写入易损坏。通过请求级实例隔离与原子写（临时文件 + 原子替换 + 互斥锁）解决，并写入 E2E 并发回归验证。
  • 企业内无外部数据源 API Key 时需保证系统完整可用与可演示：设计全链路降级体系（LLM 不可用走模板行程、向量检索降级关键词、四类感知数据源降级 Mock），任何依赖缺失下功能链路不断、仅数据降级。
跨境电商一站式 AI 运营平台 RAG&Agent 应用开发工程师 2025/08 – 2025/12
项目背景

针对外贸企业多语言沟通成本高、营销文案制作依赖资深业务员、客户咨询响应慢、企业知识难以沉淀等问题，设计并开发基于 DeepSeek 大模型 + RAG + Agent 的一站式外贸智能服务平台。系统通过 RAG 检索增强生成实现可溯源的企业知识问答客服，通过持久化术语库与翻译记忆保证 30+ 语种译法一致性，覆盖智能客服、多语言翻译、智能文案生成、知识库管理、数据洞察与管理后台六大模块，帮助外贸企业"单人驾驭多语言交流"，降低对外贸业务员岗位的依赖。

技术架构

Python + FastAPI（四层架构 + 六大模块 REST API）+ DeepSeek 大模型 + RAG（向量 + BM25 + RRF + 可插拔 Reranker）+ 可插拔 LLM / Embedding / 向量库抽象层（工厂模式）+ SSE 流式输出 + PBKDF2/HS256 JWT 鉴权 + SQLite + Docker 编排与跨平台一键启动器

主要职责
  • 设计并实现平台整体架构，采用交互层 / 编排层 / RAG 检索层 / 数据模型层四层架构，基于 FastAPI 完成六大模块 REST API；设计 LLM / Embedding / 向量库可插拔抽象层（工厂模式），默认 Mock 实现保证无 API Key 即可跑通全链路，修改配置即可无缝切换 DeepSeek、通义千问等真实模型。
  • 构建外贸领域 RAG 知识库，设计文档处理流程，实现 PDF、DOCX、TXT、CSV、Markdown 等资料解析、文本清洗（含 PII 脱敏）、语义分块、Embedding 生成和知识入库；结合向量检索 + BM25 关键词检索 + RRF 融合排序 + 可插拔重排序构建 Hybrid Retrieval 混合检索体系，回答支持知识溯源。
  • 主导 RAG 检索性能优化，BM25 索引按语料指纹缓存（文档增删自动失效重建）、向量库归一化矩阵缓存，消除每次查询的全量重建开销；文档按 doc_id 精确增删、同名自动替换，保证知识库一致性。
  • 开发智能客服 Agent，实现规则意图识别（订单 / 售后 / 产品 / 翻译）、高风险问题自动转人工、多轮上下文管理；实现 SSE 流式输出接口与前端打字机渲染，大幅降低长回答等待感。
  • 开发多语言翻译引擎，设计持久化术语库（FOB/CIF/LC 等外贸术语）注入 Prompt 保证专业译法跨语言一致；实现「进程内 LRU + SQLite 持久化」两级翻译记忆缓存，跨重启命中，重复文本零模型调用成本。
  • 开发智能文案生成模块，支持商品标题、详情描述、投放广告语、SEO 标签一键生成；基于 asyncio.gather + 异步 LLM 调用实现多段文案并发生成，生成延迟从四段串行之和降为最慢一段。
  • 设计鉴权与安全体系，基于 PBKDF2 + HS256 JWT 实现零第三方依赖认证，多角色权限控制（注册防自助提权、管理员专用角色授予接口）、CORS 白名单自适应。
  • 建立可观测性与工程化体系，Token 用量接入 LLM 真实 usage 支撑成本看板；编写 20 项冒烟 + 单元测试；实现 Docker 编排与 Windows/POSIX 跨平台一键启动器。
项目难点
  • 单一大模型服务需同时支撑智能问答、文案生成、实时翻译等多个场景，文案"一键生成"需串行调用 4 次 LLM 导致延迟叠加。通过 asyncio.gather 并发生成 + SSE 流式推送解决，多段生成延迟从串行之和降为最慢单段，客服场景实现逐字输出。
  • 外贸场景专业术语密集（FOB、CIF、L/C、MOQ 等），同一术语多语言译法不一致会直接影响合同与沟通准确性；传统关键词检索也容易遗漏语义相关知识。通过数据库持久化术语库注入 Prompt 强约束译法 + 向量/BM25 双路检索 RRF 融合解决，答案附带知识来源可溯源。
  • 知识库文档增删频繁，检索索引（BM25 统计量、向量矩阵）若每次查询全量重建，随知识库增长问答延迟将持续劣化。通过语料指纹缓存 + 增删失效重建、向量归一化矩阵惰性缓存解决，检索热路径无全量重建开销。
  • 大模型存在幻觉风险，商业客服场景不能给出无依据回答；同时高风险问题（投诉、退款、法律）不宜由 AI 处理。通过 RAG 溯源 + 关键词规则识别自动转人工兜底解决。
